# Response Signaling and Error Handling

### Learning Objectives
- Master the encoding and semantics of the four standard AXI response codes (`OKAY`, `EXOKAY`, `SLVERR`, `DECERR`).
- Contrast write response signaling (`BRESP`) on the B channel with read response signaling (`RRESP`) on the R channel.
- Distinguish between a slave-generated error (`SLVERR`) and an interconnect-generated decode error (`DECERR`).
- Understand the critical **Burst Completion Invariant** during error conditions.
- Analyze how system architectures recover from bus faults without freezing or corrupting the interconnect fabric.

---

## The Four AXI Response Types

Every AXI transaction returns a 2-bit status code indicating the outcome of the request. The four response codes are:

![AXI Response Types](images/ch6_response_types.svg)

| Response Code | Binary (`[1:0]`) | Status Name | Detailed Architectural Meaning |
|---|:---:|---|---|
| **`OKAY`** | `2'b00` | Normal Access Success | Indicates that a normal read or write transaction completed successfully. Also returned when an exclusive access reaches a slave that does not support exclusive operations. |
| **`EXOKAY`** | `2'b01` | Exclusive Access OK | Indicates that an exclusive access (read or write) was processed successfully and passed exclusive monitor checks. (See Chapter 9). |
| **`SLVERR`** | `2'b10` | Slave Error | The target slave was reached successfully, but the slave hardware could not fulfill the request (e.g., parity error, unaligned access violation, or write to read-only register). |
| **`DECERR`** | `2'b11` | Decode Error | Generated by the interconnect routing fabric when the requested address does not map to any valid slave peripheral or memory region in the system address map. |

---

## Write Response Semantics (`BRESP`)

For write transactions, the slave issues a **single** 2-bit `BRESP` status on the Write Response (`B`) channel for the entire burst:
- The slave evaluates all beats of the write burst.
- If **any** beat inside the burst produces an error, or if the entire burst cannot be serviced, the slave returns `SLVERR`.
- The response handshake must occur **only after the final write data beat** has been accepted (`WLAST = 1` and `WREADY = 1`).
- The response carries the matching transaction ID (`BID = AWID`), allowing the master to identify which outstanding burst completed.

---

## Read Response Semantics (`RRESP`)

For read transactions, the slave returns a 2-bit `RRESP` status on the Read Data (`R`) channel **alongside every individual data beat**:
- Each beat carries its own independent `RRESP` value.
- In an 8-beat burst, beats 0 through 4 could return `OKAY`, while beat 5 could return `SLVERR` (e.g., if beat 5 encountered an uncorrectable ECC error in a specific RAM block).
- Even if a beat encounters an error, the slave **must continue driving the remaining beats until the full burst length is satisfied**, asserting `RLAST` on the final beat.

## Slave Error (`SLVERR`) vs. Decode Error (`DECERR`)

Understanding the distinction between `SLVERR` and `DECERR` is fundamental to debugging SoC system faults:

![AXI Error Handling Flow](images/ch6_error_handling_flow.svg)

### Slave Error (`SLVERR`): Target Found, Operation Failed
Generated internally by the peripheral or memory controller when:
1. A master attempts to write to a read-only configuration register.
2. An unaligned 64-bit access is attempted on a slave that strictly requires 32-bit aligned boundaries.
3. An uncorrectable SRAM parity or ECC bit error is detected during a read.
4. A master with insufficient privilege (e.g., User Mode) attempts to access a protected register (`AWPROT`/`ARPROT` violation).
5. A timeout occurs inside an external memory interface (e.g., SDRAM controller precharge failure).

### Decode Error (`DECERR`): Target Address Non-Existent
Generated by the **Interconnect Fabric** itself (typically by a dedicated default "error slave" module inside the crossbar) when:
1. A master issues an address targeting an unmapped hole in the SoC address space.
2. The interconnect address decoder finds no active chip-select or slave matching `AWADDR` or `ARADDR`.
3. To prevent the bus from hanging indefinitely, the interconnect terminates the request on behalf of the nonexistent slave, absorbing the write data beats and returning `DECERR`.

## The Burst Completion Invariant

A fundamental rule of AXI protocol compliance is:

> **Protocol Invariant:**
> **An error condition does NOT permit an early termination of a burst transaction. The full burst length specified in `AxLEN` MUST be completely transferred across the data channel.**

### Why Early Termination is Forbidden:
Consider an 8-beat write burst where the slave detects an illegal address on Beat 2:
- If the slave simply terminated the burst or dropped `WREADY` LOW permanently, the master would remain hung waiting to send beats 3 through 7.
- The interconnect queues would become misaligned, deadlocking subsequent transactions.
- **The Protocol-Compliant Behavior:** The slave must assert `WREADY` and accept (or discard) all 8 beats of data through `WLAST = 1`. Then, and only then, it issues `BRESP = SLVERR` on the B channel.
- Similarly, for a read burst that suffers a decode error, the interconnect default slave returns dummy data (e.g., all 0s or all 1s) with `RRESP = DECERR` for all requested beats until `RLAST = 1`.

## System-Level Fault Recovery and CPU Exceptions

When a master receives an error response (`SLVERR` or `DECERR`):

1. **CPU Masters:** The processor core translates the AXI bus error into an asynchronous or synchronous architectural exception:
   - In Arm Cortex-A/R/M processors, a read error generates a **Data Abort Exception** or **BusFault**.
   - An instruction fetch error on the AR channel triggers a **Prefetch Abort Exception**.
   - A write error typically triggers an asynchronous **External Data Abort** or **SError** (System Error) interrupt.
2. **DMA Controllers:** Modern DMA engines halt the active descriptor channel, log the failing address and error type into status registers, and trigger an interrupt to the host CPU driver.
3. **Interconnect Stability:** Because the burst completion invariant was respected, the AXI interconnect remains completely operational and ready for subsequent transactions from other masters.

---

## Chapter Summary

- AXI provides four response codes: `OKAY` (`00`), `EXOKAY` (`01`), `SLVERR` (`10`), and `DECERR` (`11`).
- `BRESP` reports burst-level completion on the B channel; `RRESP` reports per-beat completion on the R channel.
- `SLVERR` is produced by an addressed slave that cannot fulfill the request.
- `DECERR` is produced by the interconnect when an address fails to map to any valid slave.
- **Burst Completion Invariant:** Even during an error, the full burst length must complete all handshakes up to `WLAST`/`RLAST` to prevent bus deadlocks.
- Masters trap bus errors to trigger operating system aborts, bus fault handlers, or DMA interrupt alerts.

## Review Questions

### Question 1
What is the difference between `SLVERR` and `DECERR`, and which component is responsible for generating each?
<details>
<summary><b>View Answer</b></summary>
- **`SLVERR` (Slave Error):** Generated by an addressed slave when the slave is successfully reached by the interconnect, but internal conditions prevent it from fulfilling the access (e.g., privilege violation, ECC error, write to read-only register).  
- **`DECERR` (Decode Error):** Generated by the interconnect fabric (or default error slave) when the requested address does not decode to any valid physical slave device in the system address map.
</details>

### Question 2
If a slave detects an error on the second beat of a 16-beat write burst, can it immediately assert `BVALID = 1` with `BRESP = SLVERR` and terminate the transaction?
<details>
<summary><b>View Answer</b></summary>
No. Under the AXI specification, the slave must continue the handshake and accept all 16 write data beats until the master asserts `WLAST = 1`. Only after the final beat has been transferred may the slave assert `BVALID = 1` on the B channel with `BRESP = SLVERR`. Terminating early would violate channel dependencies and hang the master.
</details>

### Question 3
Can a read burst return different `RRESP` codes for different data beats within the same burst?
<details>
<summary><b>View Answer</b></summary>
Yes. In an AXI read burst, every individual data beat carries its own 2-bit `RRESP` field. If a burst spans across multiple memory blocks and only one specific block contains an uncorrectable ECC error, the slave can return `OKAY` for the valid beats and `SLVERR` for the corrupted beat.
</details>

### Question 4
How does an operating system typically respond when an AXI master CPU core receives a `DECERR` response on an instruction fetch?
<details>
<summary><b>View Answer</b></summary>
The CPU traps the error as a synchronous Instruction Abort (Prefetch Abort). The operating system's kernel fault handler inspects the Program Counter (PC), determines that code execution jumped to an invalid unmapped memory region (often a null or wild pointer), and typically terminates the offending user process with a segmentation fault (`SIGSEGV`) or raises a fatal kernel panic if in supervisor mode.
</details>
